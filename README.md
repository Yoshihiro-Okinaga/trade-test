# リード・ラグ戦略 検証まとめ

クロス銘柄のリード・ラグ戦略（ある銘柄 `ref` の指標で別銘柄 `target` を売買する）を
総当たり探索し、walk-forward で過剰最適化を剥がして評価した記録。
本ドキュメントは、確定した結論・その根拠・残る留保を一枚に整理したもの。

---

## 1. 結論（先に要点）

- 検証を通った軸は **①（GBP_USD ← EUR_GBP）** と **④（AUD_USD ← EUR_GBP）** の 2 本。
- 両者の相関は約 0.30。合わせて持つと **実質 1.7 本分**（分散はそこそこ効くが完全ではない）。
- **★（USD_CHF ← CAD_JPY）** は①④と無相関という魅力があったが、本体が弱く **不採用**。
- **②③** は早い段階で落選。
- コストは backtest に最初から含まれている（片道スプレッド＋スワップ）。全 OOS はコスト後の手取り。
- 現時点で無条件に強い軸は無い。①④とも「薄いが本物」の水準（1 取引 +0.18〜0.23%）。

---

## 2. システムの構造

- `ref`（シグナル源）の指標を見て `target`（売買対象）を仕掛ける。
- 指標は change / sma / bb / macd / rsi / di / stoch / streak の 8 種。
  counter_trade（逆張り）、閾値幅、ラグ日数、保有日数、SMA 期間などを掛け合わせて総当たり。
- コスト：スプレッドを値幅コストとして**仕掛け時に片道 1 回**引く（`profit = POS_RATE * target_change − TRADE_COST`）。
  スワップは保有暦日数ぶん日次で加減。FX・Index・Commodity はスプレッド商品なので片道方式が正しい。
- walk-forward：全履歴のトレードを「年別 (件数, 合計, 二乗和, 勝数)」に畳み込み、
  学習窓で戦略を選び（学習 t 最大）、直後の未使用の検証窓で成績を記録。時間をずらして繰り返す。

---

## 3. 検証を通った軸

| 軸 | 組み合わせ | 指標 | rolling 8→2 の OOS | 性質 |
|----|-----------|------|--------------------|------|
| ① | GBP_USD ← EUR_GBP | di が核 | +0.231% / t≈1.9 / 255取引 | EUR/GBP の相対情報。寿命数年。 |
| ④ | AUD_USD ← EUR_GBP | 指標非依存 | +0.181% / t≈1.5（直近重視で t≈2.3） | 別市場への波及。近年ほど効く。共有通貨ゼロ。 |

### ① GBP_USD ← EUR_GBP

- 切り分けテストで、**自己モメンタム（GBP_USD 自身）でも EUR 単独（EUR_USD）でもない**ことを確認。
  - self（GBP_USD 自身）：OOS −0.02%、エッジなし。
  - EUR_USD 単独：OOS +0.05%、ほぼゼロ。
  - EUR_GBP：OOS +0.34%（anchored）。→ 効いているのは **EUR 対 GBP の相対**そのもの。
- 年減衰診断：半減期を 4〜6 年に絞ると IS_t が上がり di 選抜も増える。エッジは近年にも実在するが、
  **寿命は数年スケール**で、等重み（全期間フラット）だと窓前半の弱い年に薄められて検出が不安定になる。
- 物語としては「EUR/GBP の相対的な強弱が GBP_USD のその後の動きに効く」まで。
  「先行して察知（リード）」という時間的因果までは証明していない。

### ④ AUD_USD ← EUR_GBP

- self（AUD_USD 自身）は flat〜直近重視のどの窓でも OOS マイナス。参照の上乗せがクリーン。
- **指標が定まらない**（sma/bb/change/di が入れ替わる）が、どの指標でも cross が self に勝ち、
  cross OOS_t が全設定で +2 前後を保つ → エッジは特定指標でなく「参照関係そのもの」に宿る。
- 直近重視ほど OOS_t が締まる（2 年窓で t≈2.3）→ **①より時間的に安定した近年型**。
- 共有通貨ゼロ（EUR/GBP と AUD/USD）なので、算術的連動では説明できない本物のクロス市場関係。

### ①④の関係（集中リスク）

- 日次損益の相関 ρ = **0.295**（全取引日）／0.387（同時稼働日のみ）。
- 稼働日の重なり 51%、同時稼働日での方向一致 64%、分散低減比 0.810。
- 解釈：約半分の日は片方だけが稼働（時期がずれ分散が効く）、同時に張る日は 6 割方同方向。
  発火源が同じ EUR_GBP なぶん相関は残るが、捉える現象が違う（相対 vs 波及）ので独立性もある。
- **実質 1.7 本分**。合わせて持つ価値はあるが「2 本でリスク半減」は期待しない。

## 4. 不採用にしたもの

| 候補 | 組み合わせ | 落選理由 |
|------|-----------|----------|
| ② | NZD_USD ← EUR_GBP (rsi) | 物語（逆張りで反発を狙う）とルール（counter=False＝順張り）が矛盾。実績も薄い。 |
| ③ | USD_JPY ← GBP_AUD (bb) | OOS が期間の過半でマイナス（直近 −0.68%）。頑健性なし。 |
| ★ | USD_CHF ← CAD_JPY (bb 逆張り) | ①④と無相関（ρ≈0）だが**本体が弱い**（下記）。 |

### ★ を落とした理由（重要）

- rolling flat の cross OOS_t = 1.16。どの穏当な窓でも有意水準に届かない。
- self に勝つのは self が終始ほぼゼロだから。cross 自体はゼロと区別できない。
- 見かけのプラスは 2015-2016 の +1.195%（レアな超逆張りの単発当たり）にほぼ依存。
- 年減衰で IS_t は上がるのに OOS は下がる（IS と OOS が逆行）＝過剰最適化の兆候。
- 教訓：**無相関はエッジが本物であって初めて価値になる**。相関の美しさに引きずられず、
  一貫した基準（self 比較＋年減衰診断）で規律をもって落とした。

## 5. コストの扱い（確定）

- backtest はもともと profit から片道スプレッド（`TRADE_COST`）とスワップを引いている
  （`backtest.py` の profit 計算）。したがって walkforward / discriminate / correlate の
  **全 OOS 値はコスト後の手取り**。①+0.231%・④+0.181% もコスト込み。
- スプレッドは「買った瞬間に不利な位置から入る」コストなので**片道 1 回が正しい**。
  往復で 2 辺目を引くのは誤り（決済は普通に返る）。
- 残る現実の摩擦は**スリッページ（約定ずれ）**のみ。これはメジャー通貨・低頻度なら小さく、
  モデル化には実約定データが要るため「運用しながら実測」する性質。今は検証項目でない。
- 補足：`cost_sensitivity.py` は「往復コストを盛る」前提で作ったが、スプレッド商品には
  存在しないコストを盛ることになるため**非推奨（使わない）**。

## 6. 方法論と規律（今後の再検証のために）

- **anchored vs rolling**：anchored（開始固定で窓が伸びる）は後半フォールドが同じ前半履歴を
  共有するため、9 フォールドは独立な 9 個の証拠ではない（実質「一つの長い当てはめ」）。
  rolling（一定長でスライド）は学習の重なりが小さく、**より正直で厳しい**。
  実際 anchored の +176% は長い履歴依存で、rolling にすると大きく縮んだ。
- **年減衰診断**：学習 t を「新しい年ほど重く」計算し、半減期を振ってエッジの時間構造を見る。
  Kish の有効サンプルサイズを使い、減衰オフ（flat）では従来の t と完全一致（10 桁一致を確認済み）。
  これは**エッジの居場所を調べる診断つまみ**であって、OOS が最良になる半減期を選ぶ最適化ではない。
- **過剰最適化の罠**：min_is_t や半減期を「OOS の成績を見て」選んではいけない。
  それは学習と検証の分離を自分で破ること。コードのコメントにも警告あり。
- **自動判定を鵜呑みにしない**：nan や「候補なし」で判定文が逆の結論を出した事例があった。
  集計行の数字と突き合わせて目視で確認する。
- **後付け選抜に注意**：OOS 列を眺めて拾った候補はすべて仮説。独立した切り分けテストを
  通して初めて信用する。

---

## 7. 作成した診断ツール

- `discriminate.py` — 切り分けテスト＋年減衰診断。冒頭の TARGET / CROSS_REF / SELF_REF /
  IS_T_HALFLIVES を変えて任意の軸に適用。config の探索グリッドと [walkforward] をそのまま使う。
- `correlate_axes.py` — 軸間の日次損益相関（集中リスクの数値化）。AXES に組を並べる。
- `cost_sensitivity.py` — （非推奨）スプレッド商品には不要。

---

## 8. 残る宿題

1. **サイズ設計** — 実質 1.7 本分のリスクをどう配分するか、同時発火時の扱い。検証でなく設計の話。
2. **危機時の相関上昇** — ρ0.30 は平時の平均値。2020 年 3 月のような全通貨一斉変動時には
   跳ねうる。分散が一番欲しい局面で消えるリスクは平均相関からは見えない
   （`correlate_axes.py` を期間分割すれば平時 vs 変動時を比較できる）。
3. **スリッページの実測** — 運用しながらモデルにフィードバックする性質。

## 9. 次の分析対象

`trade_ranking_Golden_All.csv`（283,248 行）= 全パラメータ組の in-sample ランキング。
t_value 順で、5 年区切りの期間別平均（2001-2005 … 2021-）とその取引数を含む。

- これは in-sample（全期間当てはめ）なので過剰最適化を含む見方である点に注意。
  walk-forward の OOS とは別物。
- ただし期間別平均は、①④★を含む全戦略の「エッジの時間構造」を生データで確認できる。
  年減衰診断で個別に見てきたことを、全戦略に対して一望できる。
- #1 = ①（GBP_USD←EUR_GBP di）、#3 = ④（AUD_USD←EUR_GBP sma）で、これまでと整合。

分析の狙い：期間別平均から、①④のエッジが本当に近年まで持続しているか、
EUR_GBP 系以外に「全期間で安定して効く別系統」が埋もれていないか、を確認する。
in-sample である以上、良く見えた候補は walk-forward の切り分けにかけて初めて信用すること。
